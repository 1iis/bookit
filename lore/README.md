# Lore

> Product philosophy and fictional design memory for `bookit` and hyperbooks.

This directory preserves the vivid, non-normative vision behind hyperbooks.

It is not the technical spec.  
It is not corporate positioning.  
It is the taste layer: characters, talks, essays, and fictional conversations that help us remember what kind of medium `bookit` exists to enable.

For normative direction, see [`../SPEC.md`](../SPEC.md).

## Use

Use this lore when design choices become abstract.

If a decision feels technically correct but experientially dead, ask Maya.  
If a decision feels exciting but structurally vague, ask ARC.

Together they define the emotional and technical north star:

> A hyperbook should be playable, inspectable, portable, stateful, trustworthy, and able to touch the world by consent.

## Agents

- **Maya**: the archetypal player. Young, fearless, wants safe real hacking, play, agency, fourth-wall crossing.
- **An elder visionary**: a legendary-computing composite. Old enough to carry the whole lineage, technical enough to respect hard constraints, humane enough to build for Maya.
